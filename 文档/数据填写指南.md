# 数据填写指南（给投稿者）

> 想往「城堡助手」里加一个流派？照着这篇填 `data/builds.json` 就行。
> 每个字段对应界面上哪一块，下面都写清楚了。

---

## 0. 先记住三条

1. **必填项填全**，缺了会被格式校验拒绝（下表标 ⭐）；
2. **可选项不填就不显示**，不会出现空块或“待补”占位符；
3. **不确定的数值写 `待补`**，比瞎填好。

---

## 1. 卡片上会显示什么（列表页）

| 界面元素 | 字段 | 必填 |
|---|---|---|
| 流派名 | `name` | ⭐ |
| 武器 · 刻印 | `wt` + `insc` | ⭐ |
| ★评分 / 打分人数 | `rating` / `votes` | ⭐ |
| 特点标签（一行 chip） | `features` | ⭐ |
| 玩法技巧（展开后） | `tip` | ⭐ |
| 核心宝藏（展开后） | `treasureOrder` 的前 6 项 | — |
| 详情按钮 | 自动 | — |

> 作者名不在卡片上显示，只在详情页底部署名。

---

## 2. 详情页 9 块，逐块对应字段

| 顺序 | 界面区块 | 字段 |
|---|---|---|
| 头部 | 名字 / 标签 / 评分 | `name` `features` `tags` `rating` `votes` |
| 引言 | 玩法技巧（含连招要点） | `tip` + `combos` |
| 1 | 伤害参考 | `dmgLabel` + `dmg` |
| 2 | 武器刻印 | `inscEff` + `resonance` |
| 3 | 灵魂石 | `soulStones` + `soulPlan` |
| 4 | 武器、衣服 | `weaponChoices` + `transition` + `gear` |
| 5 | 宝藏怎么选 / 诅咒宝藏 | `treasures` + `treasureOrder` + `treasureNotes` / `cursed` |
| 6 | 炼金与猎人道具 | `alchemy` + `hunterItems` |
| 7 | 梦魇推荐加点 | `nightmareList` |
| 页脚 | 作者 / 来源 / 更新 | `author` `source` `updatedAt` |

## 3. 逐字段说明

### 基本信息

```jsonc
"id": "shw_revenge_sword",   // ⭐ 唯一 id，小写字母+数字+下划线
"name": "复仇战士剑盾流",      // ⭐ 保留社区叫法，别改写成书面语
"aliases": ["昂龙剑盾", "超级轮椅"],  // 玩家还会怎么叫，用于搜索
"wt": "SHW",                  // ⭐ 武器大类，只能是这 9 个之一
"insc": "shw_revenge",        // ⭐ 主刻印 id，见 inscriptions.json
"rating": 8.2,                // ⭐ 0–10
"votes": 1915,                // ⭐ 打分人数
"author": "@迷雾、",           // ⭐ 投稿人署名
"source": "抖音图文《失落城堡2流派》第7集",  // 原帖链接或出处
"updatedAt": "2026-11-12",    // ⭐ 你更新的日期
"gameVersion": "1.0.1.3"      // ⭐ 你这套是哪个版本测的
```

`wt` 可选值：`THW` 双手 · `SHW` 单手 · `STAFF` 法杖 · `DB` 双刀 · `BOW` 弓箭 · `FD` 涡炉枪 · `GUN` 火枪 · `PL` 幽影提灯 · `KA` 太刀

### 特点标签

`features`：2–5 个，每个不超过 8 字。写给玩家看的**风格概括**，不是数值。

✅ `["一顶到底", "站桩硬顶", "低操作门槛"]`
❌ `["攻击力+25%", "T0"]`

`tags`：从 `schools.json` 里选，用于「标签」筛选。

### 伤害

```jsonc
"dmgLabel": "单段伤害",   // 或 "秒伤"
"dmg": "96,366"          // 不知道就写 "待补"，这块就不显示
```

### 武器刻印

```jsonc
"inscEff": "直接攻击有 12% 概率获得 1 个复仇印记…",   // 效果原文
"resonance": {
  "code": "2-1-2",              // 共鸣选择
  "nodes": ["节点1收益", "节点2收益", "节点3收益"]
}
```

### 灵魂石

```jsonc
"soulStones": [
  { "name": "利刃", "lv": "Lv.10/10", "eff": "直接攻击伤害提升" }
],
"soulPlan": [
  { "g": "提供增伤", "items": ["利刃2", "背水2"] }
]
```

`soulStones` = 词条清单（有什么、几级、干嘛用）
`soulPlan` = 怎么分配（分组 + 具体点法）

### 武器、衣服

```jsonc
"weaponChoices": [
  { "name": "昂龙剑盾", "tag": "核心", "note": "为什么推荐" }
],
"transition": [
  { "name": "任意单手剑盾", "tag": "过渡", "note": "带盾击强化优先", "obtain": "前三关随便捡" }
],
"gear": {
  "weapon": { "name": "英勇战魂", "type": "单手武器", "rarity": "传奇",
              "atk": "88", "skill": "战魂附身", "cost": "30",
              "note": "…", "obtain": "后期传奇掉落" },
  "armor":  { "name": "诡谲混沌之铠", "type": "轻甲", "rarity": "传奇",
              "attrs": ["生命值上限 200", "攻击速度 10%"],
              "note": "…", "obtain": "后期首领掉落" }
}
```

- `weaponChoices` 的 `tag` 只能是 `核心` / `毕业` / `过渡` / `可选`
- `transition` 会被合并进「推荐清单」并自动标「过渡」，所以别在 `weaponChoices` 里重复写

### 宝藏

```jsonc
"treasures": { "chaos": ["冰霜类混沌宝藏"], "gold": ["合成金宝藏"] },

"treasureOrder": [                       // ★ 顺序 = 拾取优先级，从上到下
  { "n": "不融冰",   "r": "优秀", "t": "R" },
  { "n": "六角石头", "r": "优秀", "t": "R" },
  { "n": "冰薄荷叶", "r": "稀有", "t": "1" },
  { "n": "北风号角", "r": "稀有", "t": "1" }
],
"treasureNotes": ["开局优先拿不融冰，先把冰权重确定下来"]
```

> **`t` 是内部字段，界面上不显示。**
> 它表示该宝藏的「流派深度」（`S` 种级 / `R` 根级 / `1` / `2`），只用于**校验顺序合不合理**：
> 高一级的宝藏必须排在有低一级垫底的后面。写错顺序会被检查工具提示。

### 诅咒宝藏

```jsonc
"cursed": [
  { "name": "被诅咒的硬币", "eff": "效果 + 诅咒副作用", "verdict": "不净化" }
]
```

`verdict` 只能是 `净化` 或 `不净化`。

### 炼金 / 猎人道具 / 梦魇 / 连招

```jsonc
"alchemy":      [{ "name": "异变邪血", "eff": "每次击败首领后 +2.5% 生命/攻击" }],
"hunterItems":  [{ "name": "飞盘", "eff": "前期补充伤害" }],
"nightmareList":[ { "n": "生命锁定", "p": "65%" } ],   // p 不填显示 —
"combos":       ["盾突 → 攻击派生昂龙拳"]              // 显示在「玩法技巧」区块里
```

## 4. 投稿流程

1. Fork 仓库
2. 在 `data/builds.json` 的 `builds` 数组里**新增一个对象**（别改别人的）
3. 本地跑校验（暂未实现 CLI，先肉眼对照本指南）
4. 提 PR，PR 描述里写：**测试版本 + 依据（截图/帖子链接）**
5. 维护者核对三件事：数值来源可查、必填齐全、`gameVersion` 正确
6. 合并后自动上线

## 5. 内容口径

- **保留社区叫法**（「超级轮椅」「一顶到底」这类黑话别翻译成书面语）
- **数值只写你实测过的**，没测过写 `待补`
- **顺序就是价值**：`treasureOrder` 的排序依据是“先垫底再拿高级”，别随意调
- **不确定的别写**：宁可少一块内容，也不要写错让别人跟着打错
