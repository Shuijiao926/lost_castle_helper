# 窗口渲染：圆形 / 圆角 / 透明度

> 这篇解释一个**看起来不该是问题的问题**：为什么一个圆角浮窗在 Windows 上这么难做。
> 以及当前三种渲染模式、怎么选、试不出来时的后手。

---

## 1. 问题的本质

Electron 在 Windows 上有两条路画“非矩形窗口”，**各有硬伤**：

| 方案 | 边缘质量 | 四角 |
|---|---|---|
| `transparent: true` + CSS `border-radius` | ✅ GPU 逐像素 alpha，抗锯齿，平滑 | ❌ 部分显卡/驱动下透明合成失效 → **白角** |
| `win.setShape(rects)` 窗口区域裁剪 | ❌ Windows 区域只支持整数像素矩形，**必然锯齿** | ✅ 物理裁掉，绝无白角 |

不存在“既平滑又无白角”的纯 Electron 方案——除非把透明合成修好。

---

## 2. 三种模式（用环境变量切换）

```
LC2_WIN_MODE=alpha        默认
LC2_WIN_MODE=alpha-nogpu
LC2_WIN_MODE=shape
```

| 模式 | 做了什么 | 预期效果 | 代价 |
|---|---|---|---|
| `alpha` | 透明窗口 + `--disable-direct-composition` | 平滑；修复大部分白角 | 个别驱动仍可能白角 |
| `alpha-nogpu` | 透明窗口 + `app.disableHardwareAcceleration()` | **兼容性最强**，几乎必然无白角且平滑 | 全部软件合成，文字略软 |
| `shape` | `win.setShape()` 圆形裁剪 | 保证无白角 | 边缘整数像素锯齿 |

切换方式（PowerShell）：

```powershell
$env:LC2_WIN_MODE='alpha-nogpu'; npm run desktop
```

启动日志会打印实际模式：

```
[lc2] window mode = alpha-nogpu | shape clip = false
```

渲染层通过 URL 参数拿到模式，挂上 `win-alpha` / `win-shape` class，
shape 模式才有额外补偿样式（2% 放大 + 深色收边）。

---

## 3. 建议的试法

按这个顺序试，一次只改一个变量：

1. **`alpha-nogpu`** —— 成功率最高。历史上 Windows 透明窗口白角的经典解法就是关硬件加速。
2. **`alpha`** —— 保住 GPU，看 `disable-direct-composition` 能否修好白角。
3. **`shape`** —— 兜底：一定没有白角，接受锯齿。

选定的模式之后可以写进 `config.json` 或直接改成默认值。

---

## 4. 如果三种都不行：引入原生窗口

### 方案 A（推荐）：C# WinForms 原生分层窗口

Windows 的 `UpdateLayeredWindow` 提供**逐像素 alpha 的分层窗口**，是 Windows 上画异形窗口的标准答案（uTools、迅雷悬浮窗都是这么做的）。

```
apps/bubble-native/
├─ Bubble.csproj          .NET 8 WinForms
├─ Program.cs             创建无边框分层窗口，逐像素 alpha 绘制圆形 PNG
└─ build.bat              dotnet publish -r win-x64 -p:PublishAot=true
```

- 体积：NativeAOT 约 3–6MB（无 .NET 运行时依赖）
- 交互：鼠标事件通过本地 HTTP（`127.0.0.1:4318`）通知 Electron 主进程开合面板
- 拖拽：原生窗口自己处理，比现在更跟手
- 面板仍是 Electron 窗口，**不动**

### 方案 B：PowerShell + P/Invoke

不想引入 .NET 项目时的轻量替代：用 `Add-Type` 调 `UpdateLayeredWindow` 画圆。
启动慢（约 300ms）、进程常驻但有窗口句柄隐藏，适合验证可行性，不适合长期。

### 方案 C：换外壳

把整个客户端换成 **Tauri（Rust + WebView2）** 或 **Wails（Go）**。
它们底层也能拿到原生窗口句柄，可以做逐像素 alpha。
代价：整个渲染层要迁移，**不推荐**——为了一个悬浮球重写客户端不划算。

---

## 5. 结论

先试 `alpha-nogpu`。它的综合表现（平滑 + 无白角）在 Windows 上最稳，代价只是文字渲染略软——而我们已经通过以下手段把“软”的影响降得很低：

- 字体栈改为开源字体优先（Noto Sans SC / 思源黑体）
- 基础字号 13.5 → 14px，行高 1.6
- 图标用 `image-set` 按 DPI 选源（1x 用 64px 原图，不做放大）
- 移除所有 `scale()` 动画（缩放过程中必然发虚）

如果 `alpha-nogpu` 的观感可接受，就定它，**不必引入原生窗口**。
只有在文字实在模糊到不可接受时，才上方案 A。

---

## 6. 最终方案：原生气泡（已实现）

三种 Electron 模式在某些环境（Chromium 透明合成不可用）下都无法同时做到「平滑 + 无白角」，
因此气泡改为 **Windows 原生分层窗口**，面板仍然用 Electron。

```
apps/desktop/native/bubble.ps1        PowerShell 宿主 + 内嵌 C#
apps/desktop/src/main/nativeBubble.js 拉起脚本、行协议通信、坐标换算
```

### 为什么这样能成

| 方案 | 边缘 | 白角 |
|---|---|---|
| Electron `transparent` | 平滑 | 部分环境失效 |
| Electron `setShape` | 整数像素锯齿 | 无 |
| **原生 `UpdateLayeredWindow`** | **平滑（图内抗锯齿）** | **无（系统按 alpha 合成）** |

原理：分层窗口交给系统一张**带 alpha 的位图**，由 DWM 逐像素合成。
窗口本身不做区域裁剪，所以既没有锯齿也没有白角。uTools 的悬浮球就是这条路线。

### 实现细节

- C# 内嵌在 `bubble.ps1` 里，用 `Add-Type` 现场编译（本机零额外安装）
- **DPI 感知**：脚本第一件事调用 `SetProcessDpiAwarenessContext`，
  否则窗口会被系统按虚拟坐标二次缩放 → 整颗球发糊（这是第一版模糊的根因）
- 图标层：**3× 超采样 + 轻锐化（unsharp mask）**，小尺寸下细节更清楚
- 光环层：逐像素按角度取 HSV 色相，3× 超采样 + smoothstep 边缘羽化
- **整帧 2× 超采样再降采样**（SSAA），圆形边缘没有阶梯感
- **悬停动效是真旋转**：30fps 每帧旋转光环 7° 重绘，同时提高亮度/饱和度
- 拖拽 / 轻点都在原生窗口里处理，比 IPC 拖窗口更跟手
- 与 Electron 用 **行协议** 通信：`READY | CLICK | MOVE x,y` / `QUIT`
- 坐标：脚本输出物理像素，主进程换算成 DIP 统一存 `config.json`
- 原生启动失败或意外退出 → 自动回退 Electron 气泡窗口，热键不会失效

### 开关

```powershell
npm run desktop                     # 默认：原生气泡
$env:LC2_BUBBLE='electron'; npm run desktop   # 回退旧方案（仅调试用）
```

### 代价

- 首次启动要编译 C#（约 1–2 秒），之后进程常驻约 30–50MB
- 多一个 PowerShell 进程，杀毒软件可能提示（属于正常系统行为）
