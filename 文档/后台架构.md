# 后台架构（骨架阶段）

> 状态：**骨架已搭好，暂未启用**。当前线上数据与文件存储全部由 GitHub 承担。
> 本文说明“以后为什么要后端、长什么样、怎么切过去”。

---

## 1. 为什么现在不上后端

客户端的查询是**离线优先**的：玩家在游戏里按热键看资料，断网也得能用。
所以后端不承担“实时查询”，它真正要解决的是四件事：

1. 收集投稿（表单 + 截图附件）
2. 人工审核 → 发布
3. 分发数据包（版本号 + hash，客户端增量更新）
4. 存文件（图标、截图、封面）

其中 1、2、4 在没有后端时可以用**GitHub PR + Release** 手工顶替，成本为零。
只有投稿量上来、需要审核队列和评分防刷时，后端才值得上。

**结论：M1–M3 用 GitHub 就够，后端骨架先放着。**

---

## 2. 技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 语言 | **Node 20 LTS** | 与客户端同语言，共享 `apps/shared` 校验代码 |
| 框架 | **Fastify 5** | 轻、快、插件生态够用；比 Express 性能好，比 NestJS 轻 |
| 数据库 | **PostgreSQL** | 关系清晰（流派/版本/投稿/评分），JSONB 又能存 payload |
| ORM | **Prisma 6** | 迁移 + 类型安全，`prisma db push` 一条命令建表 |
| 文件存储 | **GitHub（当前）→ 阿里云 OSS / 腾讯云 COS（后期）** | 见第 5 节 |
| 进程管理 | PM2 或 Docker | 单机足够 |
| 反向代理 | Nginx | HTTPS + 静态文件 + 限流 |

## 4. 接口

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/health` | 公开 | 返回存储模式（postgres / json-file） |
| GET | `/api/builds` | 公开 | 流派列表（含评分汇总） |
| GET | `/api/builds/:id` | 公开 | 单个流派 |
| POST | `/api/ratings` | 公开 | `{ buildId, score }`，0–10 |
| POST | `/api/submissions` | 公开 | `{ build, meta }`，用 shared 校验 |
| GET | `/api/submissions` | 管理员 | 待审队列 |
| POST | `/api/submissions/:id/approve` | 管理员 | 通过 → 写入流派数据 |
| POST | `/api/submissions/:id/reject` | 管理员 | 驳回 + 原因 |
| GET | `/api/packages/latest` | 公开 | 数据包版本 / hash / 下载地址 |
| POST | `/api/packages/publish` | 管理员 | 发布新数据包 |

管理员现阶段用 `x-admin-token` 请求头（值来自 `.env` 的 `ADMIN_TOKEN`），正式版换账号体系。

## 5. 文件存储策略

| 阶段 | 方案 | 说明 |
|---|---|---|
| **当前** | **GitHub 仓库 + raw** | `data/*.json` 与图标直接放仓库，客户端从 `raw.githubusercontent.com` 拉；天然 CDN、零成本、有版本历史 |
| 过渡 | GitHub Release | 图标包、数据包打成 zip 放 Release 附件，避免仓库体积膨胀 |
| 后期 | OSS / COS + CDN | 投稿截图（体积大、隐私相关）必须放对象存储，不能进公开仓库 |

> 为什么截图不能走 GitHub：GitHub 仓库是**公开且永久**的，玩家投稿截图可能含个人信息；
> 而且仓库体积会迅速膨胀。所以截图从第一天就该走独立对象存储（或先存服务器本地，不入 git）。

`plugins/files.js` 已抽象成 `save(buffer, fileName)` 接口，换存储只改这个文件。

## 6. 数据流（切换后）

```
客户端启动
   ↓ GET /api/packages/latest        ← 比对本地 version + hash
   ↓ 有更新则下载 fileUrl，sha256 校验后写入 userData 缓存
   ↓ 渲染列表（离线也能用缓存）

玩家投稿
   ↓ POST /api/submissions           ← shared.validateBuild 校验
   ↓ 入库 status=PENDING
   ↓ 管理员在后台审核
   ↓ approve → 写入 Build 表 + 生成新数据包
   ↓ 客户端下次启动自动更新
```

**当前（GitHub 阶段）的替代流程**：

```
投稿 = 提 PR 改 data/builds.json
审核 = 维护者 review + merge
发布 = merge 即生效（客户端下次拉 raw 就是新数据）
```

## 7. 启动方式（骨架）

```bash
cd apps/server
cp .env.example .env      # 可选
npm install               # 装 fastify / prisma
npm start                 # 无 DATABASE_URL 时以 JSON 文件模式启动
curl http://127.0.0.1:4317/api/health
```

配数据库后：

```bash
# .env 填入 DATABASE_URL=postgresql://...
npx prisma db push
npm start
```

> 注意：骨架阶段的依赖尚未安装，`npm start` 会提示先 `npm install`；这不影响客户端运行。
