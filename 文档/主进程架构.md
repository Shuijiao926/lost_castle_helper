# 主进程架构

> 适用对象：改客户端窗口行为 / 热键 / 托盘 / 配置前先看这篇。
> 相关：[前端架构](./前端架构.md)（渲染层分层）、[客户端说明](./客户端说明.md)（运行与打包）、[窗口渲染方案](./窗口渲染方案.md)。

## 1. 重构前的问题

`src/main/index.js` 原本 1045 行，一个文件里混了 12 类职责：

- 应用生命周期、单实例锁
- 两个窗口的创建 / 显隐 / 淡入淡出
- 面板拖拽、休眠、搜索焦点
- 圆角方案探测（DWM / setShape）
- 托盘、全局热键、IPC
- 配置读写、用户印象 JSON
- 数据加载、开发热部署、孤儿进程清理

除了难维护，还藏着几个真实问题（见第 5 节）。

## 2. 拆分后的结构

```
src/main/
├─ index.js            组合根：启动顺序 · 依赖组装 · 退出清理（约 420 行）
├─ panel.js            面板窗口控制器：显隐 / 淡入淡出 / 拖拽 / 休眠 / 焦点 / 圆角
├─ bubble-window.js    Electron 气泡窗口（原生分层气泡的兜底）
├─ config.js           用户配置：校验坏坐标 · 原子写 · 防抖落盘
├─ notes-store.js      用户印象 JSON：覆盖更新 · 长度/ID 校验
├─ data.js             数据加载：包装 source 层（github / local / cache）
├─ geometry.js         窗口几何：默认位置 / 锚定 / 可见性 / 恢复（纯函数）
├─ shape.js            setShape 圆角兜底
├─ tray.js             托盘：显示气泡 / 退出
├─ shortcuts.js        全局热键：候选基础键 + 面板按键注册/注销
├─ ipc.js              IPC 白名单：参数校验后转给控制器
├─ hot-reload.js       开发热部署：renderer / data / native 监听
├─ source.js           （原有）数据源层
├─ nativeBubble.js     （原有）原生气泡 helper 封装
└─ panelShadow.js      （原有）原生阴影 / DWM / 全局点击 helper 封装
```

依赖方向：

```
index.js（组合根）
   ├─▶ panel.js ──▶ shape.js / geometry.js / panelShadow
   ├─▶ bubble-window.js
   ├─▶ tray.js / shortcuts.js / hot-reload.js / ipc.js
   ├─▶ config.js / data.js / notes-store.js
   └─▶ source.js / nativeBubble.js / panelShadow.js
```

- 纯函数（geometry）不依赖 electron；
- 存储（config / notes-store）用注入的 `fs` / `path` / `userDataDir`；
- 面板控制器（panel）通过注入的 `BrowserWindow` / `screen` / shadow helper 工作。

因此这几层都能在 `node --test` 里直接验证，不需要启动 Electron。

## 3. 启动顺序（index.js）

```
app ready
  → await 清理上次残留的 native helper        ← 必须 await（见 5.2）
  → 加载配置（坏数据自动降级）
  → 组装 geometry / notes / data / shortcuts
  → 创建面板控制器并恢复置顶状态
  → 注册 IPC
  → 启动 panelShadow helper（DWM 圆角 + 全局点击轮询）
  → panel.create()
  → 启动气泡：原生分层气泡 → 失败则回退 Electron 气泡
  → 注册基础热键（Alt+` 等）
  → 创建托盘
  → 开启开发热部署（DEV_HOT）
  → 监听显示器变化（重新夹住气泡）
```

退出时（`before-quit`）依次：标记 `isQuitting` → 清掉层级守护定时器 → 关闭热部署
→ 停原生 helper → 注销热键 → 销毁托盘 → flush 配置。

## 4. 几个关键设计

### 4.1 面板控制器（panel.js）

面板是最复杂的一块，所有状态收在控制器内部：

```js
panel.create()      // 创建窗口 + 绑定 blur/close/did-finish-load
panel.show()        // 定位 → 圆角 → 淡入 → showInactive → 通知渲染层 → 注册按键
panel.hide()
panel.toggle()
panel.startDrag(payload) / finalizeDrag()
panel.handleOutsideClick(px, py)   // 全局点击 → 收起 / 置顶时休眠
panel.wake()        // 点击面板唤醒（恢复可聚焦）
panel.setSearchFocus(on)
panel.onNativeRestart()           // helper 重启后重探圆角
```

index 只负责把它接到 IPC / 热键 / 托盘 / 原生 helper 上。

### 4.2 几何纯函数（geometry.js）

`panelBoundsFrom` / `panelVisibleSomewhere` / `resolvePanelBounds` 全部显式接收
`workArea` / `displays` / 尺寸，不在函数里读 `screen`：

- 拖拽允许移出屏幕边界（uTools 式）；
- 恢复位置时，只要还有 ≥48px 可见就保留，完全出界才夹回最近显示器。

多显示器 / 混合 DPI 的边界情况可以直接在测试里构造。

### 4.3 配置与存储

- `config.js`：读入时校验坐标必须是有限数字，坏数据降级为 `null`；
  写入用 `临时文件 + rename`，避免写一半崩溃损坏 JSON；
  气泡拖拽这类高频写入走 `saveDebounced()`（400ms），退出时 `cancel + save` flush。
- `notes-store.js`：按 buildId 覆盖更新；非法 buildId 拒绝；文本截断 200 字。

## 5. 重构顺带修掉的问题

### 5.1 原生气泡拖拽时高频写磁盘

`nativeBubble` 的 `onMove` 在拖拽时约每 8ms 回调一次，原来每次 `saveConfig()` 同步写
`config.json` → 拖一次气泡写数百次磁盘。
**修复**：改成更新内存 + `saveDebounced()`。

### 5.2 启动时可能杀掉自己刚拉起的 helper

`cleanupOrphanHelpers()` 原来是 fire-and-forget：PowerShell 查询/停止进程需要 2~3 秒，
而 `nativeBubble.start()` / `panelShadow.ensureStarted()` 紧接着就启动新 helper，
清理命令可能在新 helper 启动后才执行，把它们也杀掉。
**修复**：`cleanupOrphanHelpers()` 返回 Promise，启动流程 `await` 它；并把清理进度写日志。

### 5.3 层级守护定时器泄漏

`createBubbleWindow()` 里每次创建窗口都 `setInterval(...)`，原生气泡失败回退、
或反复重建时会叠加多个定时器。
**修复**：定时器提升到 index 的 `startTopmostWatchdog()`，全局只有一个，退出时清理。

### 5.4 配置坏数据会让面板「消失」

配置里 `panel: {x:"abc"}` 之类会让 `setBounds(NaN)` 行为异常。
**修复**：`config.sanitizeBounds()` 校验后降级。

### 5.5 缺进程级兜底与窗口安全

- 新增 `uncaughtException` / `unhandledRejection` 日志，托盘应用不再静默崩溃；
- 设置 `app.setAppUserModelId`（任务栏 / 通知身份）；
- 渲染窗口禁止 `window.open`、禁止导航到非 `file://` 地址；
- IPC 拖拽坐标做有限数字校验，避免坏参数把窗口移到 NaN。

npm run desktop:test          # 或 cd apps/desktop; node --test "test/*.test.js"
```

npm run desktop
```
