## 2. 怎么执行本文命令

- 标注 **服务器 Bash** 的命令，在当前 `ubuntu@…` 终端执行；标注 **本地 PowerShell** 的命令，在 Windows 电脑执行。
- 不要复制终端提示符 `ubuntu@…:~$`，只复制代码块里的命令。
- 每段成功后再执行下一段；出现错误，停在该步并保留完整报错。
- `<<'EOF'` 到独占一行的 `EOF` 是一个完整命令，必须一起复制。输入过程中出现 `>` 通常是在等后续内容，最后输入 `EOF` 才结束。
- `sudo` 以管理员权限执行；`#` 开头是解释用的注释；`~` 表示当前用户的家目录，当前为 `/home/ubuntu`。
- `>` 把输出写入文件，通常会覆盖已有文件；`>>` 追加；`<` 从文件读取输入。下文会说明涉及哪个文件。
- 密码和私钥留在服务器或自己的密码管理工具中；反馈问题时只提供状态、版本及报错。

除非特别标出，本教程所有命令均为 **服务器 Bash**。本版数据库不映射宿主机端口，无需在腾讯云防火墙开放 `5432`。

## 3. 环境检查与 Docker 安装（已完成，可跳过）

### 3.1 登录与检查

先通过腾讯云控制台的“登录”进入服务器。如果已经配置了 SSH 密码或密钥，也可在本地 PowerShell 中执行：

```powershell
ssh ubuntu@43.143.97.198
```

作用：连接当前服务器。用户名、地址发生变化时使用控制台的实际信息。

在服务器上执行以下只读检查：

```bash
cat /etc/os-release
uname -m
free -h
df -h /
```

| 命令 | 用途 | 本次预期 |
|---|---|---|
| `cat /etc/os-release` | 查看操作系统版本 | Ubuntu 24.04 / noble |
| `uname -m` | 查看 CPU 架构 | x86_64 |
| `free -h` | 查看内存与 Swap | 约 4GB 内存 |
| `df -h /` | 查看系统盘空间 | 当前仍有可用空间 |

### 3.2 全新 Ubuntu 安装 Docker

**当前服务器已完成本节，不重复安装。** 以下步骤保留给以后重建服务器使用；已有其他容器运行时或 Docker 安装方式的机器，应先核对已有安装。

首先更新软件目录，再安装 HTTPS 证书与下载工具：

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl
```

| 命令 | 用途 / 成功表现 |
|---|---|
| `apt-get update` | 更新可安装的软件目录，不升级已安装的软件；不能有仓库下载失败 |
| `apt-get install -y …` | 安装证书和 curl；`-y` 自动确认安装 |

创建公钥目录，并使用腾讯云软件包镜像下载 Docker 仓库公钥：

```bash
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL --connect-timeout 15 --max-time 60 https://mirrors.cloud.tencent.com/docker-ce/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
```

第一条创建目录，不是安装 Docker；`0755` 允许其他用户读取、访问目录。第二条下载文件；`-f` 遇 HTTP 错误时失败，`-sS` 隐藏进度但显示错误，`-L` 跟随跳转，连接最多等 15 秒、全程最多 60 秒，`-o` 指定保存位置。

**下载没有报错才执行：**

```bash
head -n 2 /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
```

`head` 只读前两行，第一行应为 `-----BEGIN PGP PUBLIC KEY BLOCK-----`；这只确认文件格式，apt 随后使用公钥校验仓库签名。`chmod a+r` 允许系统读取公钥，不增加写权限。

创建或更新 Docker 专用软件源文件：

```bash
sudo tee /etc/apt/sources.list.d/docker.sources >/dev/null <<'EOF'
Types: deb
URIs: https://mirrors.cloud.tencent.com/docker-ce/linux/ubuntu
Suites: noble
Components: stable
Architectures: amd64
Signed-By: /etc/apt/keyrings/docker.asc
EOF
```

`tee` 以管理员权限写文件，`>/dev/null` 隐藏重复回显。`deb` 是软件包仓库，`noble` 对应 Ubuntu 24.04，`stable` 是稳定渠道，`amd64` 对应 x86_64，`Signed-By` 指定验证仓库签名的公钥。如果另有 `docker.list` 等 Docker 源文件，先核对，避免重复配置同一个仓库。

加载新仓库并安装：

```bash
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

五个软件包依次是 Docker 引擎、命令行、底层容器运行组件、镜像构建插件和 Compose 插件。

启动并设为开机启动：

```bash
sudo systemctl enable --now docker
```

`enable` 设置开机启动，`--now` 同时立即启动。接着检查：

```bash
sudo docker --version
sudo docker compose version
sudo systemctl is-active docker
```

前两条应显示版本号，第三条应为 `active`。本文始终使用带空格的 `docker compose` 命令。

安装依据：[Docker Ubuntu 安装说明](https://docs.docker.com/engine/install/ubuntu/)、[腾讯云 Docker 软件包镜像安装示例](https://cloud.tencent.com/document/product/213/46000)。

## 4. 修复 Docker Hub 镜像下载（当前从这里开始）

安装 Docker 的 **apt 软件源** 与下载容器的 **镜像仓库** 是两条网络链路。前者已经成功，不代表后者可用。

当前两条实际报错分别是 `i/o timeout` 和 `connect: connection refused`，发生在访问 `registry-1.docker.io` 时。容器尚未启动，不能据此认定 Docker 安装失败。

### 4.1 检查 Docker 是否已有配置

```bash
sudo cat /etc/docker/daemon.json
```

作用：只读现有配置。

- 返回 `No such file or directory`：没有配置文件，继续 4.2。
- 已有 JSON 内容：保留原配置，先不要运行 4.2 的创建命令；需要把 `registry-mirrors` 合并进去，不能丢掉其他字段。
- 已有 `registry-mirrors` 且含本节地址：直接做 4.3 的验证，不重复添加。

### 4.2 首次创建镜像加速配置

仅在 4.1 确认文件不存在时执行。先创建目录，`-p` 表示已有目录也能执行：

```bash
sudo mkdir -p /etc/docker
```

再创建 Docker 后台配置：

```bash
sudo tee /etc/docker/daemon.json >/dev/null <<'EOF'
{
  "registry-mirrors": [
    "https://mirror.ccs.tencentyun.com"
  ]
}
EOF
```

作用：让 Docker 拉取 Docker Hub 镜像时优先使用腾讯云镜像加速。该地址按腾讯云文档用于云内访问，是否可用以这台服务器实际拉取结果为准。[腾讯云轻量服务器镜像加速说明](https://cloud.tencent.com/document/product/1207/45596)

### 4.3 验证配置，再让它生效

```bash
sudo dockerd --validate --config-file /etc/docker/daemon.json
```

作用：检查 Docker 配置是否合法，不启动第二个 Docker 后台服务。预期为 `configuration OK`；报错时先修复 JSON，不继续重启。

验证成功后执行：

```bash
sudo systemctl restart docker
sudo systemctl is-active docker
```

第一条重启 Docker 以加载配置；第二条确认恢复为 `active`。**重启会影响已有容器，当前尚无成功部署的业务容器，适合在此阶段操作。** 以后已有业务时，按维护窗口操作。

查看后台实际加载的加速地址：

```bash
sudo docker info --format '{{json .RegistryConfig.Mirrors}}'
```

作用：只输出镜像加速地址列表。预期包含 `https://mirror.ccs.tencentyun.com`，末尾有无 `/` 均可。显示地址只代表配置已加载，不代表镜像已下载成功。

### 4.4 验证测试容器

```bash
sudo docker run --rm hello-world
```

作用：本地没有镜像时先下载，再创建并运行测试容器。`--rm` 在运行结束后删除测试容器，镜像仍保留。成功标志是 `Hello from Docker!`。

成功后下载 PostgreSQL 17 镜像：

```bash
sudo docker pull postgres:17
```

`pull` 只下载镜像，不启动数据库。`17` 固定大版本，后续更新仍可能取得新的 17.x 镜像。预期显示镜像已下载或已是最新版本。

如果仍超时或拒绝连接，停在这里，按第 10 节收集信息。不要把开放服务器入站 `443` 或 `5432` 当成修复镜像下载的办法：这里失败的是服务器向外访问仓库。

## 5. 建立独立的部署目录

**前提：4.4 的两条命令都成功。** 本节开始会在服务器上创建项目目录和数据库。

### 5.1 创建目录

```bash
mkdir -p ~/lc2-deploy
cd ~/lc2-deploy
install -d -m 0700 secrets backups
```

| 命令 | 用途 |
|---|---|
| `mkdir -p ~/lc2-deploy` | 在 ubuntu 家目录中创建部署目录；已存在时保留内容 |
| `cd ~/lc2-deploy` | 进入该目录；以下 Compose、备份命令均在这里执行 |
| `install -d -m 0700 secrets backups` | 创建仅当前用户可进入的密码、备份目录 |

部署目录与以后上传的源码目录分开；即使更换源码，数据库卷与备份也不跟着删除。

### 5.2 生成数据库密码

先安装密码生成工具；已安装时会保留当前可用版本或按 apt 规则更新这个软件包：

```bash
sudo apt-get install -y openssl
```

首次生成密码：

```bash
(
  umask 077
  set -o noclobber
  openssl rand -hex 32 > secrets/postgres_password
)
```

| 内容 | 用途 |
|---|---|
| `(...)` | 在临时子 shell 中执行，避免更改当前终端的后续行为 |
| `umask 077` | 新文件只允许当前用户读写 |
| `set -o noclobber` | 密码文件已存在时拒绝覆盖；重跑时遇到此提示应保留旧文件 |
| `openssl rand -hex 32` | 生成 32 字节随机值，以 64 个十六进制字符输出 |
| `> secrets/postgres_password` | 把密码存入文件，不在终端打印 |

只检查文件长度，不显示密码：

```bash
wc -c < secrets/postgres_password
```

本方法预期为 `65`（64 个字符加换行）。不是该长度时先检查上一步，不启动数据库。如果是本来就有的密码文件，不要为追求这个长度而重新生成密码。

### 5.3 创建 Compose 文件

仓库中的标准配置为 [deploy/server/compose.yaml](../../deploy/server/compose.yaml)。只用腾讯云终端时，可直接复制下面整段，在 `~/lc2-deploy` 中创建同样的文件。**已有 `compose.yaml` 时先比对内容，不直接覆盖已运行的配置。**

```bash
cat > compose.yaml <<'EOF'
name: lc2

services:
  db:
    image: postgres:17
    restart: unless-stopped
    environment:
      POSTGRES_DB: lc2
      POSTGRES_USER: lc2_admin
      POSTGRES_PASSWORD_FILE: /run/secrets/postgres_password
    secrets:
      - postgres_password
    volumes:
      - pgdata:/var/lib/postgresql/data
    mem_limit: 1g
    shm_size: 128mb
    healthcheck:
      test: ['CMD-SHELL', 'pg_isready -U "$${POSTGRES_USER}" -d "$${POSTGRES_DB}"']
      interval: 10s
      timeout: 5s
      retries: 6
      start_period: 20s
    logging:
      driver: json-file
      options:
        max-size: '10m'
        max-file: '3'

volumes:
  pgdata:

secrets:
  postgres_password:
    file: ./secrets/postgres_password
EOF
```

`cat > … <<'EOF'` 把文本原样写入当前目录，不是执行 YAML。此处不需要 `sudo`，部署目录属于 ubuntu。

| 配置 | 含义 |
|---|---|
| `name: lc2` / `db` | Compose 项目名与服务名，后续命令用 `db` 指定数据库 |
| `image: postgres:17` | PostgreSQL 官方镜像，固定在 17 大版本 |
| `restart: unless-stopped` | 异常退出或 Docker 启动后尝试恢复；手动停止的容器保持停止 |
| `POSTGRES_DB` / `POSTGRES_USER` | 首次初始化创建 `lc2` 库和 `lc2_admin` 管理账号 |
| `POSTGRES_PASSWORD_FILE` / `secrets` | 从挂载的文件读取密码，不把密码写进 YAML |
| `pgdata:/var/lib/postgresql/data` | PostgreSQL 17 数据放入命名卷，容器重建时仍保留 |
| `mem_limit: 1g` | 数据库容器内存上限 1GiB，不是预占 1GiB，也不是整机内存上限 |
| `shm_size: 128mb` | 设置容器共享内存大小 |
| `healthcheck` | 周期性检查 PostgreSQL 是否接受连接，`$$` 留给容器里的 shell 展开变量 |
| `logging` | 单份日志约 10MB，最多保留 3 份轮转日志，控制容器日志占用 |
| 没有 `ports` | 不向服务器公网或宿主机映射数据库端口 |

本机 Docker 的项目名会生成类似 `lc2_pgdata` 的卷。不要随意更换 `name` 或卷名，否则可能连到另一份新数据库。

`lc2_admin` 是镜像初始化创建的数据库超级用户，用于本阶段初始化、验收和备份；后续业务接入时另建普通应用账号。密码、用户名和初始化数据库变量只在空数据目录首次初始化时生效，**改密码文件不会自动修改已有数据库账号的密码**。

PostgreSQL 18 及以上的默认数据目录规则不同，不能直接把本配置改为 `postgres:latest`。配置依据：[PostgreSQL 官方镜像](https://hub.docker.com/_/postgres)、[Compose secrets](https://docs.docker.com/compose/how-tos/use-secrets/)、[日志轮转](https://docs.docker.com/engine/logging/drivers/json-file/)。

## 6. 启动并验收数据库

以下命令均在服务器 `~/lc2-deploy` 中执行。重连终端后，先重新进入该目录：

```bash
cd ~/lc2-deploy
```

### 6.1 检查配置

```bash
sudo docker compose config --quiet
```

作用：校验 Compose 配置；没有输出且返回命令提示符表示通过。该检查不代表密码正确或数据库能启动。

### 6.2 启动并等待健康

```bash
sudo docker compose up -d --wait --wait-timeout 120 db
```

作用：创建项目网络、数据卷及数据库容器。`-d` 后台运行，`--wait` 等待运行 / 健康状态，最多等 120 秒，`db` 指定本次只启动数据库。第一次会初始化数据库，关闭 SSH 不会关闭后台容器。[Compose up 说明](https://docs.docker.com/reference/cli/docker/compose/up/)

超时时不删除卷，先看状态和日志：

```bash
sudo docker compose ps
sudo docker compose logs --tail=80 db
```

`ps` 应显示 `healthy`；`logs --tail=80` 只查看最近 80 行，不删除日志。失败时根据日志处理，不反复清空重建。

### 6.3 验证库、账号与版本

```bash
sudo docker compose exec -T db psql -U lc2_admin -d lc2 -c 'SELECT current_database(), current_user, version();'
```

| 参数 | 含义 |
|---|---|
| `exec -T db` | 在已运行的数据库容器里执行命令，不分配交互终端 |
| `psql` | PostgreSQL 客户端 |
| `-U lc2_admin` / `-d lc2` | 指定数据库用户和数据库 |
| `-c 'SELECT …'` | 执行一次只读 SQL 并退出 |

预期显示数据库 `lc2`、用户 `lc2_admin` 和 PostgreSQL 17.x。

再验证使用密码通过 TCP 连接，而不只是容器内本地 socket 连接：

```bash
sudo docker compose exec -T db sh -c 'PGPASSWORD="$(cat /run/secrets/postgres_password)" psql -h 127.0.0.1 -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "SELECT 1;"'
```

作用：在容器内读取密码文件，只给这次 `psql` 连接使用；`-h 127.0.0.1` 强制 TCP 登录。预期得到一行数值 `1`，不会在终端打印密码。这里只设置该次命令的环境变量，不修改数据库密码。

### 6.4 检查数据卷与端口

```bash
sudo docker volume inspect lc2_pgdata
sudo docker compose port db 5432
```

第一条查看数据库卷的信息，证明数据使用命名卷。第二条检查宿主机端口映射；按本配置**没有公开映射，应提示未发布端口或没有映射结果**，不是故障。容器内部仍使用 5432。

到这里，只能记为“数据库容器已就绪”。当前尚无应用业务表，查询不到流派表属于正常状态。

## 7. 数据库备份与恢复演练

### 7.1 导出数据库

在服务器 `~/lc2-deploy` 中，按顺序执行：

```bash
backup_file="backups/lc2-$(date -u +%Y%m%dT%H%M%SZ).dump"
sudo docker compose exec -T db pg_dump -U lc2_admin -d lc2 -Fc > "$backup_file"
```

第一条把带 UTC 时间戳的文件名存进当前 shell 的 `backup_file` 变量；第二条从运行中的数据库导出 custom 格式备份。`-Fc` 指定格式，`>` 把容器输出保存到**宿主机**备份文件。

**导出命令报错时，该文件可能为空或不完整，不算备份成功。** 成功后继续检查：

```bash
ls -lh "$backup_file"
sudo docker compose exec -T db pg_restore --list < "$backup_file"
```

`ls -lh` 查看文件大小；`pg_restore --list` 读取备份目录，检查格式可读取，不恢复也不覆盖数据库。备份能够列出内容，不等于已验证完整恢复，继续做 7.3 的演练。[PostgreSQL 备份说明](https://www.postgresql.org/docs/17/backup-dump.html)

### 7.2 保存一份到自己的电脑

使用 WinSCP 等已有 SSH 文件传输工具，从服务器 `/home/ubuntu/lc2-deploy/backups/` 下载 `.dump` 文件到自己的电脑。部署配置 `compose.yaml` 以及密码文件也应分别妥善保存。

如果已配置本地 SSH 登录，也可在**本地 PowerShell**执行：

```powershell
scp 'ubuntu@43.143.97.198:~/lc2-deploy/backups/*.dump' .
```

作用：把备份下载到 PowerShell 当前目录；最后的 `.` 表示本地当前目录。数据库与备份都留在同一台服务器，不能应对整机丢失。

`pg_dump` 备份单个数据库，不包含创建整个实例的数据库角色。当前管理角色由 Compose 首次初始化创建；以后增加普通应用账号后，要同时保存账号创建 / 授权的迁移方案，在新服务器恢复数据前先准备所需角色。

### 7.3 恢复到新测试库，不覆盖业务库

以下回到**服务器 Bash**，在刚完成 7.1 的同一终端中执行；如果重连了终端，需要先给 `backup_file` 重新赋值为实际存在的备份路径，再继续。

```bash
restore_db="lc2_restore_$(date -u +%Y%m%d%H%M%S)"
sudo docker compose exec -T db createdb -U lc2_admin "$restore_db"
sudo docker compose exec -T db pg_restore -U lc2_admin -d "$restore_db" --exit-on-error < "$backup_file"
sudo docker compose exec -T db psql -U lc2_admin -d "$restore_db" -c 'SELECT current_database();'
```

| 命令 | 用途 / 成功表现 |
|---|---|
| 设置 `restore_db` | 生成带时间戳的新库名 |
| `createdb` | 创建新测试库；失败就停止，不对已经存在的库继续恢复 |
| `pg_restore … --exit-on-error` | 把备份恢复到新库，遇错立即退出；不会自动切换业务连接 |
| `psql … SELECT` | 确认可以访问恢复后的新库 |

有业务表后还需核对表数量、关键记录及关联关系。当前初始化库没有业务表时，不会凭空恢复出流派数据。演练创建的测试库先保留；正式恢复到业务库、清理测试库另行明确操作，不在此处提供清库命令。[pg_restore 说明](https://www.postgresql.org/docs/17/app-pgrestore.html)

本版是手动备份流程；业务开始写入前还需补齐定时备份、保留周期及定期异机恢复验证。

## 8. 常用维护命令

先在服务器执行 `cd ~/lc2-deploy`，再选择需要的一条，**不要整表逐条运行**。

| 命令 | 做什么 / 影响 |
|---|---|
| `sudo docker compose ps` | 查看本项目容器状态 |
| `sudo docker compose logs --tail=80 db` | 查看数据库最近日志 |
| `sudo docker stats --no-stream` | 查看容器即时 CPU、内存占用，输出一次后退出 |
| `df -h /` | 查看系统盘可用空间 |
| `sudo docker system df` | 查看镜像、容器、卷等 Docker 空间占用，不做清理 |
| `sudo docker compose stop db` | 停止数据库，数据卷保留；业务会暂时无法连接 |
| `sudo docker compose up -d --wait --wait-timeout 120 db` | 启动 / 应用本项目配置并等待健康 |
| `sudo docker compose restart db` | 重启数据库，有短暂中断，不更新镜像 |
| `sudo docker compose down` | 停止并删除本项目容器、网络，命名卷默认保留；服务中断 |

**不要给 `compose down` 加 `-v`，也不要直接清理数据库卷。** 删除卷会删除本教程中真实持久化的数据，只有确认数据可丢弃或已有可恢复备份时，才能另行安排清理。

更新 PostgreSQL 时先备份、记录当前镜像版本，并安排维护窗口。跨大版本升级需要迁移方案，不能用更换镜像标签代替升级流程。

## 10. 已遇到的问题与排查

| 现象 | 当前可以判断什么 | 下一步 |
|---|---|---|
| 公钥下载 `Connection reset by peer` | 下载过程中连接被重置，文件可能没有生成 | 使用第 3 节腾讯云软件包镜像，下载成功后再检查文件 |
| `chmod … No such file or directory` | 目标文件不存在，通常是前一步下载失败的连带结果 | 修复下载，不继续添加指向不存在公钥的仓库 |
| 拉取镜像超时 / 拒绝连接 | 连接仓库阶段失败，尚未启动容器 | 第 4 节检查加速配置并实际重新拉取 |
| `invalid character …` / 配置验证失败 | Docker 后台 JSON 配置不合法 | 对照逗号、引号、括号；验证成功后再重启 |
| `docker compose` 找不到配置 | 当前目录没有部署 YAML，或没有指定文件 | 进入 `~/lc2-deploy`，确认 `compose.yaml` 在此 |
| secret 文件不存在 | 密码文件未创建、目录不对或未上传 | 检查 `secrets/postgres_password`，不把密码贴到聊天里 |
| 数据库 `unhealthy` 或反复重启 | 镜像已运行，但数据库尚未就绪 | 看 `compose logs`、磁盘空间和容器资源占用，不先删数据卷 |
| 修改密码文件后仍登录失败 | 已有库不会因文件改动自动修改账号密码 | 保留原密码，安排数据库内的密码轮换，不清卷重建 |
| 健康接口显示 postgres，但没有真实表 | 当前日志标签不代表实际持久化实现 | 按第 9 节完成仓储、迁移和真实读写验收 |

镜像问题仍未解决时，在服务器执行以下只读检查：

```bash
sudo systemctl is-active docker
sudo docker info --format '{{json .RegistryConfig.Mirrors}}'
getent ahostsv4 mirror.ccs.tencentyun.com
curl -I --connect-timeout 10 --max-time 20 https://mirror.ccs.tencentyun.com/v2/
sudo journalctl -u docker -n 60 --no-pager
```

| 命令 | 用途 |
|---|---|
| `systemctl …` | 确认 Docker 后台仍在运行 |
| `docker info …` | 查看实际加载的镜像加速地址 |
| `getent ahostsv4 …` | 使用服务器当前解析配置查询镜像域名 IPv4 |
| `curl -I …` | 只请求 HTTP 响应头；200 或认证类响应说明端点至少有响应，但不证明某镜像存在；超时、DNS 或证书错误按实际报错处理 |
| `journalctl …` | 查看 Docker 最近 60 条服务日志，不持续跟踪，不修改配置 |

反馈上述输出和失败命令即可；日志如果含代理账号、密码或令牌，先隐藏这些值。不要用关闭 TLS 验证、写死 Docker Hub IP 或随意更换系统 DNS 作为通用修复方法。
