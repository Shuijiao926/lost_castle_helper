# 服务端说明

> 状态：**P1 完成** —— 领域骨架可运行，无数据库也能跑通「查询 / 评分 / 投稿 / 审核 / 发布」全链路。
> 设计依据见 [后端设计-DDD](后端设计-DDD.md)。
>
> 云服务器环境准备与数据库容器操作见 [服务器部署指南](服务器部署指南.md)。配置数据库连接后，图鉴与已发布流派查询使用 Java 维护的 PostgreSQL 数据；评分、投稿和数据包仍使用 JSON。未配置连接时保留原 JSON 模式。

## PostgreSQL 图鉴查询

先在仓库根目录生成已有 Prisma Client：

```bash
npx --no-install prisma generate --schema apps/server/prisma/schema.prisma
```

该命令只生成客户端代码，不连接数据库、不建表。不要为此运行 `db:push`、`db:migrate` 或 Prisma 数据库迁移：`catalog` schema 由 Java Flyway 管理，旧 Prisma 模型不能用于创建这套图鉴表。

- `DATABASE_URL`：PostgreSQL 连接串，适用于本地联调。
- `DATABASE_URL_FILE`：保存完整连接串的 UTF-8 文件路径，适用于挂载密钥文件的部署方式。
- 两项只能设置一项；都不设置时使用 JSON。不要将密码或连接串提交到 Git 或贴入聊天。
- Node 账号仅需 `catalog` schema 的 USAGE，以及 `import_batch`、`active_release`、`item` 三张表的 SELECT 权限，不需要写权限或读取 `source_document`。

`GET /api/catalog` 从一次数据库查询中取得生效批次与条目，返回九类集合及内容哈希版本。保留原四类集合键，并补充武器物品、防具、灵魂石、诅咒宝藏和梦魇效果；刻印兼容 `weaponTypeId` 与 `wt`。公开 DTO 使用字段白名单并递归剥离 `t`、`depth`，不直接返回数据库完整载荷。

`GET /api/health` 在配置连接后返回 `persistence: mixed`，并用 `persistenceDetails` 分别标明各业务的存储方式。该接口是服务存活信息，不代表数据库已经可用，也不代表评分或投稿已经入库。

数据库连接失败、没有生效批次或批次条目不完整时，图鉴接口返回 HTTP 503，不悄悄回退本地 JSON。应用关闭时释放自己创建的 Prisma 连接。

## PostgreSQL 流派查询

Java 的 `V2__build_storage.sql` 新增 `game.build`、`game.build_revision` 和 `game.published_build`。先上传新 Java JAR、重建管理镜像，再使用已有命令执行 `--lc2.catalog.command=migrate`；它会沿用 catalog 中的 Flyway 历史，只追加 V2，不改写 V1 或清空已有图鉴。

在服务器给现有 Node 只读账号追加最小授权：

```bash
sudo docker compose exec -T db psql -U lc2_admin -d lc2 -v ON_ERROR_STOP=1 -c "GRANT USAGE ON SCHEMA game TO lc2_catalog_reader; GRANT SELECT ON game.published_build TO lc2_catalog_reader;"
```

Node 仅读取该已发布视图，不授予主表、历史表或写入权限。迁移和授权完成后，再部署新版 Node 镜像和 Compose 配置；无需重建已有密钥。缺表或缺权限会返回 503，不回退 JSON。

- `GET /api/builds` 支持原筛选、排序和分页；先合并当前评分再排序、分页，total 表示分页前有效数量。
- `GET /api/builds/:id` 对草稿、待审、下架和不存在记录统一返回 404。
- 详情通过共享 schema 白名单输出，并递归剥离内部 t/depth；管理侧完整载荷不直接出接口。
- 流派默认草稿；只有 Java 明确导入 PUBLISHED 状态的记录才进入玩家接口。正式流派仍为空时，列表返回 items=[]、total=0，属于正确状态。
- Java 负责流派新增、更新和状态维护；旧 Node 投稿审核入口在数据库模式下不能写流派，会返回冲突。评分、投稿自身当前仍存 JSON，后续再接数据库。
- 图鉴和流派共用一个 Prisma Client，关闭服务时释放连接；健康接口仍为 mixed，但 persistenceDetails.builds 为 postgres。

## Docker 部署（图鉴与流派查询阶段）

使用现有 PostgreSQL Compose 项目，新增 Node 服务；当前只绑定服务器本机 `127.0.0.1:4317`，暂不开放公网端口。镜像运行时只读，以非 root 用户运行，JSON 运行数据保存在独立命名卷中。

Windows PowerShell 在原前端/Node 仓库执行：

```powershell
Set-Location D:\Project\lost_castle_helper
node scripts/package-server.js
scp out/lc2-node-deploy.tar.gz ubuntu@43.143.97.198:/home/ubuntu/lc2-deploy/
```

打包脚本仅包含服务端、共享校验、明确列出的真实 JSON 和部署文件，不包含桌面端、mock、node_modules、运行数据或密钥；不要求先提交或推送 Git。

服务器首次构建：

```bash
cd ~/lc2-deploy
mkdir -p node-build
tar -xzf lc2-node-deploy.tar.gz -C node-build
sudo docker build -t lc2-node:local -f node-build/deploy/server/Dockerfile.node ./node-build
```

构建安装锁文件内的服务端依赖、生成 Linux Prisma Client；不安装 Electron，不执行数据库迁移。需要能访问 Node 基础镜像、Debian 软件源及 npm/Prisma 下载服务。

确认已创建 `lc2_catalog_reader` 账号，并按上节授予三张表的只读权限，然后生成密钥配置：

```bash
cd ~/lc2-deploy
python3 node-build/deploy/server/configure-node-secrets.py
cp node-build/deploy/server/compose.node.yaml compose.node.yaml
sudo docker compose -f compose.yaml -f compose.node.yaml --profile node config --quiet
```

脚本只在当前部署目录操作：隐藏输入数据库只读账号密码，将经过 URL 编码的连接串写入 `secrets/node_database_url`，另生成随机管理令牌写入 `secrets/node_admin_token`。Compose 分别通过 `DATABASE_URL_FILE`、`ADMIN_TOKEN_FILE` 传入文件路径，不把实际内容写到镜像或 Compose 环境变量。脚本不修改数据库账号和密码。

已有密钥时默认停止；维护者明确需要重建时才使用 `--replace`，这会重建两份密钥并使旧管理令牌失效。不要输出或上传这些密钥文件。

启动和核对：

```bash
sudo docker compose -f compose.yaml -f compose.node.yaml --profile node up -d node
sudo docker compose -f compose.yaml -f compose.node.yaml --profile node ps
curl -fsS http://127.0.0.1:4317/api/health
curl -fsS http://127.0.0.1:4317/api/catalog | python3 -c 'import json,sys; c=json.load(sys.stdin)["catalog"]; print(json.dumps({"version":c["version"],"counts":{k:len(v) for k,v in c.items() if isinstance(v,list)}},ensure_ascii=False,indent=2))'
```

容器健康检查实际访问图鉴和流派接口，因此依赖数据库连接、查询权限、生效图鉴及 V2 流派视图；空流派列表允许通过健康检查。首次图鉴基准为九类合计 1121 条，版本哈希应与 Java `status` 一致。后续数据变化以实际批次为准。

这一阶段图鉴和流派查询已接 PostgreSQL；评分、投稿等仍是 JSON 仓储，不代表用户业务已完成持久化，也不代表桌面端已切换到远程接口。当前阶段不要运行 `down -v`、Prisma 建表或替换已有数据库 Compose 文件。

## 目录结构：按大功能职责划分，模块内 DDD 分层

```
apps/server/src/
├─ index.js                    启动入口（只做装配 + 启动日志）
├─ app/                        组合根（跨模块）
│  ├─ config.js                ★ 唯一读取 process.env 的地方，所有默认值集中于此
│  ├─ container.js             依赖注入：决定用哪套仓储 / 安全组件
│  ├─ http-server.js           Fastify 装配 + 按 api/routes 注册
│  ├─ admin-auth.js            鉴权（头名与口令来自配置）
│  └─ adapters.js              hash / clock 技术适配器
├─ api/                        ★ 所有接口的公共定义（唯一的地方）
│  ├─ routes.js                路由表：方法 / 路径 / 权限 / handler 名
│  ├─ handlers.js              请求处理（薄，只做参数解析 + 调用例）
│  └─ errors.js                领域错误 → HTTP 状态码
├─ shared/                     跨模块共用
│  ├─ logger.js                ★ 统一日志组件（分级别、带 scope、可 child）
│  ├─ kernel/errors.js         领域错误（含 RateLimitedError / BadRequestError）
│  ├─ kernel/event-bus.js      进程内领域事件
│  ├─ kernel/shared-kernel.js  加载前后端共用校验（@lc2/shared）
│  └─ infrastructure/json-database.js
└─ modules/                    ★ 每个目录 = 一个限界上下文
   ├─ catalog/                 图鉴：武器 / 刻印 / 宝藏 / 流派分类
   ├─ builds/                  流派聚合根 + 不变量
   ├─ submissions/             投稿与审核
   ├─ ratings/                 评分
   ├─ publishing/              数据包版本与 hash
   └─ security/                安全管控：请求指纹 + 滑动窗口限流
      └─ 每个模块内：domain/ · application/ · infrastructure/
```

**纪律**：

- 路由只在 `api/routes.js` 声明；模块里不再出现 HTTP 相关代码
- 环境变量只在 `app/config.js` 读取；业务代码不碰 `process.env`
- 日志只用 `shared/logger.js`；业务代码不直接 `console.log`
- 跨模块只能通过 application 用例或仓储接口，不 import 对方 domain 内部实现
- `domain/` 禁止出现 `fastify` / `@prisma/client` / `fs` / `crypto`

## 接口（声明于 `src/api/routes.js`）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/health` | 公开 | 健康检查（持久化模式） |
| GET | `/api/catalog` | 公开 | 武器 9 / 刻印 27 / 流派分类 29 |
| GET | `/api/builds` | 公开 | 卡片列表（`weaponType` `inscriptionId` `sort` `limit` `offset`） |
| GET | `/api/builds/:id` | 公开 | 详情（已剥离内部字段） |
| POST | `/api/ratings` | 公开 | `{ buildId, score }`，0–10，**有限流** |
| POST | `/api/submissions` | 公开 | `{ payload, meta }`，必须勾选授权，**有限流** |
| GET | `/api/submissions` | 管理员 | 待审队列 |
| POST | `/api/submissions/:id/approve` | 管理员 | 通过 → 写回流派 |
| POST | `/api/submissions/:id/reject` | 管理员 | 驳回（必须填原因） |
| GET | `/api/packages/latest` | 公开 | 最新数据包版本 |
| POST | `/api/packages/publish` | 管理员 | 生成新数据包（sha256 + 版本递增） |

管理员鉴权：请求头名 `x-admin-token`（`API_ADMIN_HEADER` 可改），值来自 `ADMIN_TOKEN`。

## 安全管控模块（`modules/security`）

| 层 | 内容 |
|---|---|
| domain | `evaluateWindow()` 纯函数（滑动窗口）、`RateLimitPolicy` 值对象 |
| application | `RateLimiter.assert(action, key)`，超限抛 `RateLimitedError` |
| infrastructure | 请求指纹（`sha256(ip\|ua)[:32]`，不存明文）、限流计数持久化 |

**设计要点**：

1. **指纹不存明文**：只存 `sha256(ip + '|' + ua)[:32]`，换 IP 或 UA 即视为新指纹
2. **计数落盘**：写 `data/runtime/security-limits.json`，重启不能绕过限流
3. **先校验后限流**：非法请求（如分数越界）不消耗配额，避免误伤
4. **策略可配**：`RATING_RATE_LIMIT` / `SUBMISSION_RATE_LIMIT` 等环境变量控制

默认策略：

| 动作 | 默认限制 | 说明 |
|---|---|---|
| `rating` | 20 次 / 分钟 | 同指纹同窗口 |
| `submission` | 5 次 / 10 分钟 | 人工审核成本高，门槛更高 |

## 已实现的领域规则

| 规则 | 位置 |
|---|---|
| 字段级校验（与客户端同一份 `@lc2/shared`） | `modules/builds/domain/build.js` |
| 图鉴引用校验（武器类型、刻印归属） | 同上（严格拒绝 / 宽松降级警告） |
| 宝藏顺序不可重复 | 同上 |
| **内部字段（宝藏深度 `t`）绝不外泄** | `stripInternal()`，单测覆盖 |
| 投稿必须勾选授权 | `modules/submissions/domain/submission.js` |
| 只有 `PENDING` 能被审核 | 同上 |
| 评分同指纹只保留最后一次 | `modules/ratings/domain/rating.js` |
| 限流（评分 / 投稿） | `modules/security/` |
| 数据包版本递增 + 稳定序列化（同内容同 hash） | `modules/publishing/domain/package.js` |
| 单条脏数据不拖垮列表 | `modules/builds/application/use-cases.js`（返回 `skipped`） |

## 终端乱码（Windows）

控制台默认 936(GBK)、Node 输出 UTF-8，中文日志会乱码。
`npm run start` / `npm run dev` 已内置 `chcp 65001`；若直接 `node src/index.js`，请先执行：

```powershell
chcp 65001
```
