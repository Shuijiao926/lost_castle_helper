# LC2 Helper 需求文档（PRD）v0.3

> 《失落城堡2》流派速查助手　｜　Windows　｜　配套：[总纲](./方案总纲.md) · [架构](./技术架构.md) · [原型](./原型/index.html)

---

## 1. 背景与目标

### 1.1 问题

《失落城堡2》的流派知识高度分散：刻印归属、灵魂石优先级、梦魇加点取舍、局内宝藏门槛，散落在 wiki 各页、TapTap 帖、视频里。玩家实际痛点是**打游戏时没法查**——切屏会掉焦点、全屏会黑、联机时会掉线。

### 1.2 目标

| 目标 | 度量 |
|---|---|
| G1 不切屏查资料 | 从按热键到看清目标内容 ≤ 3 秒 |
| G2 纯键盘可完成全部操作 | 鼠标操作路径 = 0（可选，不强制） |
| G3 不干扰游戏 | 呼出/收起过程中游戏窗口不失去焦点、不最小化 |
| G4 内容可信且不过期 | 每条内容带版本号/更新日/来源；过期自动标灰 |
| G5 零侵入 | 不写游戏目录、不读游戏内存、不注入 DLL |

### 1.3 非目标

- 不做游戏内注入 UI（BepInEx 路线另案）
- 不做自动操作/脚本/挂机
- 不做账号数据读取
- 不做移动端

## 2. 用户与场景

| 用户 | 场景 | 关键诉求 |
|---|---|---|
| 开荒玩家 | 刚开始玩，不知道双刀怎么配 | 从武器进，看到 2 个流派，照抄 |
| 中层玩家 | 能过梦魇 1–2，想上 3 | 看梦魇加点组合 + 灵魂石优先级 |
| 老玩家 | 只想知道这版本什么最强 | 强度榜一屏看完，不看细节 |
| 联机玩家 | 朋友开黑，不能用插件 | 纯显示工具，联机也能用 |

**典型使用时序**（决定界面层级顺序）：

```
营地 → 选武器/流派 → 看刻印（局外） → 看灵魂石 → 叠梦魇 → 进关
  ↓
局内 → 开宝箱前 → 看宝藏选择顺序 → 勾选已拿 → 看门槛进度
```

所以树的第三层顺序固定为：**刻印 → 灵魂石 → 梦魇加点 → 宝藏怎么选**。

## 4. 信息架构（纯树 · v0.5 冻结）

> v0.5：**取消局内/局外区分**，四块内容一次全展示；新增「标签」页签。

```
[图鉴]      [强度榜]      [标签]      ← 三个并列页签，Tab 循环

[图鉴]
武器大类（第1层，9 个，副标题带形态：重剑/大刀 · 重斧/重锤…）
 └ 刻印（第2层，每类 3 个：宝藏猎人 + 2 专属，共约 27）
    └ 玩家流派（第3层，★社区梗名构筑）
        └ 四块内容（第4层）→ 右侧详情面板，一次全展示
            ├ 梦魇加点
            ├ 灵魂石
            ├ 宝藏怎么选（含第5层：具体宝藏条目，可勾选已拿）
            └ 连招要点

[强度榜] 按 T0/T1/T2 排「玩家流派」
[标签]   按宝物流派标签聚合，跨武器跨刻印
```

节点类型固定 6 种：`武器` / `刻印` / `玩家流派` / `内容块` / `条目` / `宝藏分组`。渲染器按类型出不同样式。

**层数分配的理由**：420px 面板里树超过 3 层缩进会把文字挤没；而第 4–5 层是"读"的内容，放右侧可滚动区更合适。

## 5. 功能需求

优先级：`P0` = M1 必须有；`P1` = M2–M3；`P2` = M4–M5。

### FR-01 气泡常驻　[P0]

- 首次启动在屏幕右侧中部生成 36×36 圆角气泡，半透明（默认 0.75）
- 可拖动；松手后自动吸附最近屏幕边缘；多显示器时吸附到所在显示器边缘
- 位置、透明度、大小持久化，重启恢复
- 气泡上不显示文字，仅显示当前流派的元素色

**验收**：拖动到任意位置 → 重启 → 位置不变；把显示器拔掉 → 自动回落到主屏可见区域。

### FR-02 全局热键呼出/收起　[P0]

- 默认 `Alt + \``，可在设置里改
- **常驻只注册 1 个热键**；面板展开时才临时注册 `↑ ↓ ← → Tab Space Esc Enter 1–9`，收起立即注销
- 热键被占用时自动尝试备选键位，并在托盘气泡提示最终生效键
- 面板展开/收起动效 ≤ 150ms

**验收**：面板展开时游戏仍处于前台且未失去焦点；按 `Esc` 关闭后，游戏内方向键立即恢复正常。

### FR-03 纯树浏览与键盘导航　[P0]

| 键 | 行为 |
|---|---|
| `↑ ↓` | 在当前可见节点列表内移动光标 |
| `→` | 展开节点 / 进入子层级 |
| `←` | 折叠节点 / 退回父层级 |
| `Enter` | 展开该节点详情（第4层条目） |
| `1–9` | 跳转到当前层第 N 个节点 |
| `/` | 进入搜索 |
| `Tab` | 切换 `局外 / 局内` 视图 |
| `Esc` | 逐级退出：详情 → 树 → 收起面板 |

- 光标位置、展开状态持久化（下次打开回到上次位置）
- 树默认展开到「流派」层，第 3 层默认折叠（避免面板过高）

**验收**：全程键盘可从启动状态走到"某个流派 → 宝藏 → 某件宝藏详情"。

### FR-04 节点与四块内容渲染　[P0]

**三类节点各有一套详情布局：**

| 节点 | 详情面板内容 |
|---|---|
| 武器大类 | 武器机制说明（如双手=蓄力值三槽、单手=架势值+12帧精确防御）、形态列表、其下刻印清单 |
| 刻印 | 刻印效果原文、解锁条件、对应梦魇深度、适用形态、**该刻印下的玩家流派列表** |
| 玩家流派 | 四块内容 + 数据版本/更新日/来源 |

**四块内容（挂在玩家流派下，一次全展示，顺序固定）：**

| 顺序 | 内容块 | 渲染形式 |
|---|---|---|
| 1 | 梦魇加点 | 两栏：推荐叠 / 建议避开，附"可打到梦魇 X" |
| 2 | 灵魂石 | 有序列表：优先级序号 + 词条名 + 一句话理由 |
| 3 | 宝藏怎么选 | 三档分组：根级铺垫 / 1级核心 / 2级上限，每条带稀有度色标与勾选框 |
| 4 | 连招要点 | 无序列表：武器机制要点、派生链、取消时机 |

> 「刻印」不再作为内容块——它是第 2 层节点本身。
> 玩家流派详情顶部还有一张「身份卡」：核心武器 / 流派标签 / 别名。

**验收**：任意玩家流派的四块内容都能完整展示、不溢出（长文本可滚动）。

### FR-05 三页签与标签索引　[P0]

- `Tab` 在图鉴 / 强度榜 / 标签 三个页签间循环
- **标签页**：列出全部宝物流派标签（雷击、投掷、暴击、召唤物、护盾、爆燃火球、毒雾、周期性触发…），每个标签后面显示包含它的玩家流派数量
- 选中某个标签 → 列出全部相关玩家流派（可跨武器、跨刻印），`→`/回车跳转到该流派详情
- 标签数据直接复用游戏内宝藏的流派标签，不自造词表

**验收**：在图鉴/强度榜/标签任一处按 `→`，都能跳到对应玩家流派详情。

### FR-05b 玩家流派身份卡　[P0]

玩家流派详情顶部固定展示一行身份信息：

- **核心武器**：这套玩法依赖的具体武器（如「溜溜球」）
- **流派标签**：宝物流派标签 chip 列表
- **别名**：社区同义叫法（如「漂浮溜溜球 / 雷击溜溜球」），供搜索命中

**验收**：搜索/标签筛选能通过别名与标签命中该流派。

### FR-06 宝藏勾选与门槛进度　[P1]

- `Space` 勾选/取消「本局已拿」，`Backspace` 撤销上一步
- 实时计算：各流派标签的当前最深深度 → 可拿上限 → 高亮"现在可以拿"的宝藏
- 顶部显示进度：`1级 ✓　2级 还差 1 件`
- 勾选状态在本次运行内保留；关闭面板不丢，重开游戏（进程重启）清空

**验收**：勾选一件 1 级宝藏后，"2 级上限"分组内符合门槛的条目立即从灰色变为可拿色。

### FR-07 强度榜　[P1]

- 独立 Tab，一屏陈列所有流派，按 `T0 / T1 / T2` 分组
- 每条显示：流派名、武器类型、强度档、适用梦魇深度、上手难度、更新日期
- 支持按武器类型筛选（按 `←→` 切筛选条件）
- 点击/回车跳到该流派的树节点

**验收**：一屏内可看到全部流派（超出一屏时可用 `↑↓` 滚动），且能一键跳转到详情。

### FR-08 搜索　[P1]

- `/` 唤起搜索框（此时需要输入 → 临时激活一个真实输入框）
- 支持搜：流派名、刻印名、武器名、宝藏名、灵魂石词条
- 结果按类型分组，回车跳转

**验收**：输入"暴击"能同时命中含该词的流派、灵魂石词条、宝藏。

### FR-09 数据版本与过期提示　[P1]

- 每条流派带 `适用版本`、`更新日期`、`来源链接`
- 当前游戏版本与数据版本不一致时：该条目标灰 + 顶部提示"数据可能过期"
- 游戏版本来源：用户手动填写 或 从 `meta.json` 的 latest 字段读取（不读游戏文件）

### FR-10 社区数据更新　[P2]

- 从 GitHub raw 拉取 `data/` 最新 JSON，sha256 校验后替换
- 拉取失败保留本地旧数据，不阻塞启动
- 设置页显示"数据最后更新时间"和"检查更新"按钮

### FR-11 设置页　[P2]

热键自定义、透明度、气泡大小、默认视图、开机自启、数据目录、清空已拿记录。

### FR-12 首次启动引导　[P2]

一页说明：这是什么、怎么呼出、数据来源与许可、不修改游戏。可"不再显示"。

### FR-13 托盘与单实例　[P2]

托盘菜单：显示/隐藏、设置、检查更新、关于、退出。重复启动时唤起已有实例。

```
        ┌──────────── 启动 ────────────┐
        ▼                              │
   [BUBBLE 气泡态] ──Alt+`──▶ [TREE 树态] ──Enter──▶ [DETAIL 详情态]
```

## 8. 数据需求与社区维护

### 8.1 内容口径

每个流派必须提供四块，缺一块则该流派在树上显示"内容待补"，不允许只写一半就当完成。

### 8.2 必填字段（玩家流派）

`name` / `aliases[]` / `coreInscription` / `coreWeapons[]` / `tags[]` / `tier` / `maxNightmare` / `gameVersion` / `updatedAt` / `source` / 四块内容（`nightmare` / `soulstones[]` / `treasures[]` / `combos[]`）

可选：`altInscriptions[]` / `coreTreasures[]` / `contributors[]`

### 8.3 归类规则（决定流派挂在哪）

社区流派的核心未必是刻印——有的靠武器机制（溜溜球），有的靠宝藏标签（雷击）。因此：

1. `coreInscription` **必填**，是挂在哪个刻印节点下的唯一依据
2. `altInscriptions` 可填，表示能换着用的刻印
3. **不依赖刻印的纯武器/宝藏驱动玩法 → `coreInscription` 填该武器大类的「宝藏猎人刻印」**（通用位）
4. `tags` 使用游戏内宝藏的流派标签，作为第二维度索引

> 效果：「射手雷击流」既能从 `弓箭 → 轰鸣游侠` 找到，也能在标签页按 `雷击` 筛出来。
> 命名规则：**保留社区原名**（「虚浮的闪电溜溜球」不要规范化），仅用 `aliases` 补同义词。

### 8.3 社区维护流程

1. 贡献者 fork → 改 `data/builds.json` 对应条目 → 提 PR
2. PR 必须填写：改动理由 + 依据（截图/wiki 链接/实测）+ 适用游戏版本
3. 维护者核对 3 件事：数值来源可查、四块齐全、`gameVersion` 正确
4. 合并后由 CI 跑 JSON Schema 校验，失败即拒绝
5. 每条记录保留 `contributors[]` 字段，署名贡献者

### 8.4 冲突与过期处理

- 同一流派出现两种说法：分 `variants` 并存，不删任何一方，各自标注适用版本
- 游戏大版本更新：`meta.json` 提升 `gameVersion` → 所有旧条目自动进入"待复核"状态（标灰 + 列在待办清单）

## 10. 风险与开放问题

| 风险 | 对策 |
|---|---|
| 内容工作量远大于代码 | M1–M4 先用占位数据；内容按武器类型分批发；用 `fetch_wiki.py` 打底 |
| 强度榜主观、易引战 | 只标"社区共识档位"，标注投票来源；不排序内部名次 |
| 版本更新导致全面过期 | `gameVersion` 机制 + 批量待复核清单 |
| 玩家用独占全屏 | 首启引导里明确要求无边框窗口 |

**开放问题**

1. 强度榜分级用 `T0/T1/T2` 还是 `S/A/B/C`？
2. 灵魂石优先级的依据是"数值"还是"实测手感"？（决定要不要收集实测样本）
3. 是否需要"流派变体（variant）"字段？（同一流派的不同取舍，如高爆伤版 / 续航版）
4. 梦魇加点是"一套通用组合"还是"按梦魇深度给多套"？（当前按多套设计）
