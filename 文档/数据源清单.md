# 数据源清单

> 先回答一个常见误解：**「不商用」不等于「可以随便拿」**。
> 著作权和平台协议是两套独立的规则，非商用只是**降低了**一部分风险，不产生使用权。

---

## 一、法律边界：能拿什么、不能拿什么

### 1.1 事实可以拿，表达不可以抄

中国《著作权法》不保护**思想、事实、操作方法**，只保护**表达形式**。

| 内容 | 性质 | 能否使用 |
|---|---|---|
| 武器叫「仪典黄铜锤」、攻击力 49/59/69/78 | 事实 | ✅ 可用 |
| 某流派「先拿根级、再拿 1 级」这个结论 | 事实 / 方法 | ✅ 可用 |
| 作者写的攻略正文、配图、排版 | 表达 | ❌ 不能照搬 |
| 作者录制的视频、截图 | 作品 | ❌ 未经许可不能转载进产品 |

**结论**：流派「该拿什么、什么顺序」是**事实性信息**，我们自己去玩、自己总结、或者请作者**授权投稿**，都没问题。
但**不能把作者的原文、原图、原视频搬进客户端**。

### 1.2 平台协议是另一层限制

抖音、小红书、B 站、TapTap 的用户协议都明确禁止「未经许可的抓取、转载、商用」，**即使你不收费**：

| 场景 | 是否合规 |
|---|---|
| 自己看攻略，然后自己玩、自己记录结论 | ✅ |
| 把结论整理成自己的结构化数据（不抄原文） | ⚠️ 灰色但通常可接受，需注明灵感来源 |
| 爬取平台内容入库 | ❌ 违反平台协议 |
| 把作者原文/截图放进客户端 | ❌ 侵犯著作权，非商用也不豁免 |
| 请作者授权后转载（注明作者+链接） | ✅ 最稳 |

### 1.3 「汇编」还有一层保护

某人整理的「全流派图鉴大全」如果体现了选择与编排的独创性，可构成**汇编作品**。
整表复制有风险；**少量引用 + 注明出处**相对安全。

### 1.4 我们的红线

```
✅ 用 wiki（CC BY-NC-SA 明确授权）
✅ 用自己实测的数据（事实）
✅ 用作者授权的投稿（表单勾选授权）
✅ 引用少量并注明出处
❌ 爬取抖音/小红书/B站内容
❌ 搬运作者原文、截图、视频
❌ 使用解包/破解的游戏资源
❌ 商用（广告/收费/订阅）
```

## 二、数据源清单

### A 类：合法且可自动化（优先）

|---|---|---|---|---|---|

| A6 | 维护者/团队成员实测 | 数值、机制、掉落、顺序 | 自有 | 人工记录 | ❌ 人工 |

| B2 | 小红书笔记 | 同上 | 同上 | 同上 |

| B6 | 微信公众号文章 | 同上（平台协议最严） | 同上 | 同上 |

> B 类**唯一合规的进入方式**：作者主动投稿并勾选「允许本工具展示」，
> 或者我们以作者身份自己玩出来、用自己的话重写为结构化数据。

### C 类：自有与贡献者

| # | 来源 | 说明 |
|---|---|---|
| C1 | 玩家投稿（表单） | 表单必须包含授权勾选项 + 作者署名 + 原帖链接 |
| C2 | GitHub PR | 提交即视为同意 CC BY-NC-SA 4.0（仓库已有声明） |
| C3 | 维护者整理 | 自己实测/自己撰写，不受第三方限制 |

### D 类：禁止使用

| 来源 | 原因 |
|---|---|
| 破解/解包的游戏资源、内存读取 | 违反用户协议，且技术上也不做 |
| 商业攻略站内容（游民、3DM、17173 等） | 未经授权转载 |
| 未授权的 wiki 镜像站 | 二次转载，来源不可靠 |
| 任何「代练/外挂/脚本」相关内容 | 与工具定位冲突 |

## 三、每条数据都要带「来源身份证」

数据库与 JSON 里，每条**流派**记录必须包含：

```jsonc
{
  "author": "作者名 / 维护者",
  "source": "https://原帖链接",
  "sourceType": "wiki | self-test | authorized-submission | pr",
  "license": "CC-BY-NC-SA-4.0",
  "gameVersion": "1.0.1.3"
}
```

图鉴数据（武器/刻印/宝藏）则在数据包层面记录：

```jsonc
{
  "sources": [
    { "type": "wiki", "url": "https://lc2.huijiwiki.com/", "license": "CC-BY-NC-SA-4.0", "importedAt": "..." }
  ]
}
```

**用途**：
1. 合规可追溯（被质疑时能说明来源）
2. 内容过期时能找到原始出处复核
3. 贡献者可获得署名

## 四、署名规范

必须署名的地方：

| 位置 | 内容 |
|---|---|
| 客户端「关于」页 | 数据来源：失落城堡2中文维基（灰机）+ 各流派作者 |
| 流派详情页底部 | 原作者 + 原帖链接（已有 `source` 字段） |
| 仓库 README | 数据来源与许可声明 |
| `LICENSE-DATA` | CC BY-NC-SA 4.0 全文 |

**署名格式**：

```
数据来源：失落城堡2中文维基（CC BY-NC-SA 4.0）
流派作者：@某某某 · 原帖：https://...
```

## 六、如果收到投诉怎么办

1. **立即下架**该条数据（`status = ARCHIVED`，客户端下次更新即消失）
2. 保留操作日志（谁、何时、依据）
3. 与投诉方沟通，确认是「事实」争议还是「表达」争议
4. 事实争议 → 修复数据；表达争议 → 删除并改为自写版本

**预防措施**：投稿表单强制要求授权勾选，没有勾选一律不入库。
