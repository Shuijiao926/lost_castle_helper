# data — 种子数据

客户端与服务端**共用**的一份数据。客户端打包进安装包（离线可用），服务端用它做初始化。

## 文件

| 文件 | 内容 | 谁维护 |
|---|---|---|
| `builds.json` | ★ 流派数据（一个流派 = 一条记录，含 9 个区块内容） | 社区投稿 |
| `weapons.json` | 9 大武器类型 + 形态 | 维护者（游戏改动时） |
| `inscriptions.json` | 27 个灵魂刻印（9 类 × 3） | 维护者 |
| `schools.json` | 29 个宝物流派标签 | 维护者 |
| `package.json` | 数据包版本（服务端发布时生成，可选） | 服务端自动生成 |
| `ratings.json` | 评分记录（服务端生成，**不入 git**） | 服务端 |
| `submissions/` | 投稿待审（**不入 git**） | 服务端 |

字段规范见 [../apps/shared/schema/build.schema.json](../apps/shared/schema/build.schema.json)，
填写说明见 [../文档/数据填写指南.md](../文档/数据填写指南.md)。

## 修改流程（当前：GitHub 阶段）

```
1. Fork 仓库
2. 改 data/builds.json（只加自己的，别动别人的）
3. 本地跑校验
4. 提 PR：写清测试版本 + 依据（截图/帖子链接）
5. 维护者核对 → merge
6. 客户端下次启动拉到新数据（打包版走 GitHub，开发版读本地）
```

## 校验

```bash
# 校验整个 builds.json
node scripts/validate-data.js

# 校验单个文件
node scripts/validate-data.js data/builds.json
```

## 约定

- **保留社区原名**（「超级轮椅」「一顶到底」不要改写）
- `treasureOrder` 的顺序就是拾取优先级，**顺序本身是内容**，别随意调
- 数值只写实测过的，没测过写 `待补`
- 不确定宁可不填——缺字段只是不显示，填错会误导别人
