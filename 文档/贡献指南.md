# 贡献指南

两种贡献：**加数据**（最常见）和**改代码**。

---

## 一、贡献流派数据

不需要会编程，改 JSON 即可。

### 步骤

1. Fork 仓库
2. 在 `data/builds.json` 的 `builds` 数组里**新增一条**（不要改别人的）
3. 本地校验：

```bash
node scripts/validate-data.js
```

4. 提 PR，标题写 `data: 新增 xxx 流派`
5. PR 描述必须包含：
   - **测试版本**（如 `1.0.1.3`）
   - **依据**：截图 / 原帖链接 / wiki 页面
6. 维护者核对三件事：字段齐全、来源可查、`gameVersion` 正确

### 填什么

完整字段说明见 [文档/数据填写指南.md](./数据填写指南.md)，规范见 [../apps/shared/schema/build.schema.json](../apps/shared/schema/build.schema.json)。

几条硬规矩：

- **保留社区原名**（「超级轮椅」「虚浮的闪电溜溜球」别改成书面语）
- `treasureOrder` 的**顺序就是拾取优先级**，顺序本身是内容，不能乱排
- 数值只写实测过的，没测过写 `待补`
- 可选字段宁缺勿错——缺了只是不显示，填错会误导别人

## 二、贡献代码

### 环境

- Node.js 20+（见 `.nvmrc`）
- Windows（客户端唯一目标平台）

```bash
git clone <repo>
cd lost_castle_helper
npm install
npm run desktop
```

### 提交前自检

```bash
# 数据校验
node scripts/validate-data.js

# 语法检查（所有 JS）
node --check apps/desktop/src/main/index.js
node --check apps/server/src/app.js
```

PR 会跑同样的检查（`.github/workflows/validate.yml`）。

### 代码约定

| 项 | 约定 |
|---|---|
| 语言 | 客户端渲染层用原生 HTML/CSS/JS，**不引入前端框架**（体积与构建复杂度不划算） |
| 注释 | 解释「为什么这么做」，不解释「这行在干嘛」 |
| 错误处理 | 数据加载类失败一律降级 + 日志，**不允许白屏** |
| 路径 | 不写死绝对路径，统一从 `src/main/index.js` 的常量取 |

### 三条不能破的底线

1. **不注入游戏进程**、不读内存、不改游戏文件
2. **不抢焦点**（`focusable: false` + `showInactive()`）
3. **面板热键成对注册/注销**，否则玩家游戏内方向键会失灵

## 四、提交规范与版本号

- **提交信息**：Conventional Commits，如 `feat(desktop): ...`、`fix(renderer): ...`、`docs: ...`
- **版本号自动递增**：`npm install` 后会启用 `.githooks/pre-commit`，每次提交自动 `patch +1`
  （`0.1.0 → 0.1.1`），不需要手改 `package.json`
- **正式发布**：维护者执行 `npm run release`（`major +1`，`0.9.3 → 1.0.0`），
  提交 `release: vX.Y.Z` 并打 tag
- **提交前质量门**：

```bash
npm run validate             # 数据校验
npm test                     # 数据 + 桌面测试 + 服务端测试
node scripts/check-links.js  # 文档内链
node scripts/version.js check
```

完整开发规范见根目录 [AGENTS.md](../AGENTS.md)。
