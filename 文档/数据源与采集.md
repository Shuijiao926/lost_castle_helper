# 数据源与采集方案

> 各类数据源能不能用、许可边界与署名要求，见 [数据源清单](./数据源清单.md)。

> 结论先说：**灰机 wiki 是最好的结构化数据源**，它有 MediaWiki API 和整套游戏数据模块（Lua 表），
> 不需要解析 HTML。社区流派内容则必须人工录入，不能爬。

---

## 一、数据分两类，处理方式完全不同

| 类型 | 内容 | 变化频率 | 来源 | 获取方式 |
|---|---|---|---|---|
| **参考数据（图鉴）** | 武器、刻印、宝藏、防具、灵魂石、枚举字典 | 跟版本走，几个月一次 | 灰机 wiki 数据模块 | **程序自动采集** |
| **流派内容** | 某流派拿什么宝藏、先拿哪个、配什么装备、怎么加点 | 每周都有新流派 | 抖音 / 小红书 / TapTap 作者 | **人工投稿 + 审核**，不自动抓 |

这两类必须分开建模、分开存储、分开发布节奏。混在一起会导致「图鉴更新一次，所有流派都要重审」。

## 二、参考数据源：灰机 wiki（已实测可用）

### 2.1 API 能力

```
https://lc2.huijiwiki.com/api.php
```

| 用途 | 接口 |
|---|---|
| 列出分类 | `?action=query&list=allcategories` |
| 分类成员 | `?action=query&list=categorymembers&cmtitle=Category:宝藏` |
| 读取页面 | `?action=parse&page=仪典黄铜锤&prop=wikitext` |
| 读取模块 | 同上，`page=模块:LC2/ItemType/Data` |
| 图片地址 | `?action=query&prop=imageinfo&iiprop=url` |

### 2.2 关键数据模块（已确认存在）

| 模块 | 大小 | 内容 |
|---|---|---|
| `模块:ItemLink/Data` | 145 KB | 物品 ID → 链接数据（名称、图标等） |
| `模块:ItemLink/IdentifyData` | 547 KB | 物品鉴定/描述数据 |
| `模块:LC2/ItemType/Data` | ~1 KB | 物品大类：武器 / 防具 / 宝藏 / 灵魂石 / 炼金材料… |
| `模块:LC2/ItemRareType/Data` | 小 | 稀有度枚举 |
| `模块:LC2/ItemLevel/Data` | 小 | 等级枚举 |
| `模块:LC2/PassivePropsClassification/Data` | 1.7 KB | **宝物流派分类 30 种**（火属性 / 暴击 / 召唤物 / 护盾…） |
| `模块:LC2/PassivePropsType/Data` | 632 B | 宝藏类型枚举 |
| `模块:LC2/PassivePropsClassifyDepth/Data` | 小 | **宝藏深度：种级 / 根级 / 1级 / 2级**（内部用，不对玩家展示） |
| `模块:LC2/GemSlotType/Data` | 小 | 灵魂石孔位类型 |
| `模块:LC2/ChestType/Data` | 小 | 宝箱类型 |

> 实测样例（宝藏深度）：
> ```
> [PassivePropsClassifyDepth.Seed] = '种级'
> [PassivePropsClassifyDepth.Root] = '根级'
> [PassivePropsClassifyDepth.Level1] = '1级'
> [PassivePropsClassifyDepth.Level2] = '2级'
> ```
> 这正是我们界面上「按顺序拿」背后的机制——但**只作为排序依据，不展示给玩家**。

### 2.3 页面内容是什么样

物品页面本身很薄，数据在模块里，页面只负责展示：

```
{{物品自描述
|ID=DB_008
}}
== 技能 ==
*向目标投掷一枚风暴之锤...
```

所以采集策略是：**先抓模块拿到全量结构化数据，再用页面 wikitext 补技能描述/历史**。

### 2.4 分类清单（可用于校验采集完整性）

已确认存在这些分类：

```
武器类：单武器 / 双手武器 / 双刀 / 弓弩 / 法杖 / 涡炉枪 / 幽影提灯
装备类：防具 / 轻甲 / 布甲

```

## 三、采集流水线设计

```
① 快照（raw）
   scripts/fetch-wiki.js
   → data/raw/wiki-<时间戳>/*.json
   只做「拉下来存着」，不做任何解释

② 解析（parse）
   Lua 表 → 结构化 JSON
   data/raw/... → data/normalized/*.json

③ 转换（map）
   外部字段 → 领域模型（防腐层）
   data/normalized → data/catalog/
     weapons.json  inscriptions.json  treasures.json  schools.json

④ 校验（validate）
   scripts/validate-data.js + 领域规则
   不通过 → 不能进入发布流程

⑤ 发布（publish）
   打版本包 → 客户端拉取
```

**为什么要 ① 和 ② 分开**：wiki 数据会变，出问题时必须能回放「当时抓的是什么」，
不能只留转换后的结果。

### 关键技术点：Lua 表解析

模块内容是 Lua 源码：

```lua
local ItemType = require('Module:LC2/ItemType')
return {
  [ItemType.Weapon] = '武器',
  [ItemType.PassiveProps] = '宝藏',
}
```

处理方式：写一个**只支持子集**的解析器（`scripts/lib/lua-table.js`）：

- 支持：`return { ... }`、`[key] = value`、字符串、数字、布尔、嵌套表、`--` 注释
- 不支持：函数、循环、`require` 求值 → 遇到就记警告并跳过该键

不要试图跑 Lua（引 VM 太重），也不要正则硬啃（嵌套会错）。

## 四、社区流派数据：必须人工

| 为什么不能自动抓 | 原因 |
|---|---|
| 版权 | 抖音/小红书图文是作者原创，抓取再分发属于侵权（与 wiki 的 CC 协议不同） |
| 质量 | 同一个流派有多个版本，说法不一，需要人判断 |
| 结构 | 内容是「先拿 A 再拿 B」这种顺序知识，自然语言里没有结构 |
| 时效 | 版本一改就过期，必须有 `gameVersion` 字段和过期标记 |

**流程**：作者授权投稿 → 填写结构化表单（客户端/网页） → 审核 → 归入对应刻印。

投稿表单字段就是 [数据填写指南](./数据填写指南.md) 里的字段，不需要另建一套。

## 五、图标资源

| 来源 | 方式 | 许可 |
|---|---|---|
| wiki `File:` 页面 | `action=query&prop=imageinfo&iiprop=url` 拿原图 URL，下载到 `apps/desktop/assets/icons/` | CC BY-NC-SA 4.0，需署名 |
| wiki 缩略图 CDN | 直接引用 `huiji-thumb.huijistatic.com`（**现状，不推荐**） | 断网不可用、随 wiki 变动失效 |

**结论**：图标必须离线打包。一次性抓取 → 按 `itemId` 命名 → 打进安装包 → 数据文件里只存 `itemId`。

---

## 六、合规红线（必须遵守）

1. **不得商用**：数据 CC BY-NC-SA 4.0 → 不能放广告、不能收费、不能做付费订阅
2. **必须署名**：客户端「关于」页 + 仓库 README 都要写数据来源
3. **相同协议**：我们产出的数据文件也必须 CC BY-NC-SA 4.0
4. **采集礼貌**：请求间隔 ≥ 1 秒，带 `User-Agent`，只抓需要的页面，不并发轰炸
5. **社区内容授权**：投稿时必须让作者勾选「允许本工具转载」（表单里加字段，存证）

## 拉取到的数据存哪里

| 环节 | 位置 |
|---|---|
| 客户端拉取缓存 | `<userData>/data-cache/builds.json`（含 `__hash` / `__version`，`LC2_CACHE_DIR` 可改目录） |
| 客户端本地种子 | 仓库 `data/*.json`（打包进 `resources/data/`） |
| 服务端种子数据 | `DATA_DIR`（默认仓库 `data/`） |
| 服务端运行时数据 | `RUNTIME_DIR`（默认 `data/runtime/`）：评分、投稿、限流计数 |
| 服务端数据包文件 | `RUNTIME_DIR/packages/<version>.json` + `RUNTIME_DIR/package.json` 元信息 |

数据源地址可用 `LC2_DATA_URL` 指向自建服务或镜像；当前默认 GitHub raw，
客户端链路是「远端 → 本地缓存 → 仓库种子」三级降级。
